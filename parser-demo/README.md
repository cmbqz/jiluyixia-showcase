# 量词剥除：白名单 vs 黑名单

一个 100 行的可运行示例，说明「中文文本清洗时，量词该不该剥」为什么不能用黑名单判断。

```bash
node test.js       # 30 条断言，全部通过 → 退出码 0
node quantifier.js # 打印对比例子
```

---

## 问题

记账类产品要处理这种输入：

```
买了一杯咖啡15   →  名称「咖啡」，金额 15
```

自然想到「把量词剥掉」。第一版我们写的是**黑名单**：列出哪些量词不能剥。

失败了。黑名单是开放集合，永远有表外说法击穿：

```
买了盒仔茶12     →  剥掉「盒」→「仔茶」     ❌ 商品名被毁，信息不可恢复
```

「盒仔茶」是一个真实存在的饮品名。它不在任何黑名单里。

---

## 修法：反转方向

不枚举「哪些不能剥」，只剥「能确认该剥的」。每次最多剥一层，三选一：

| 规则 | 例子 | 为什么安全 |
|---|---|---|
| **(a) 数词 + 量词** | 一杯咖啡 → 咖啡 | 有数词时量词是修饰，剥完名字仍可读 |
| **(b) 数词 + 个 / 孤立个** | 一个苹果 → 苹果 | 同上 |
| **(c) 量词 + 品类白名单** | 盒月饼 → 月饼 | 命中白名单，说明「盒」在这里确实是量词 |

其余一律不动。

### 关键区别：(a) 可以无条件剥，(c) 必须查白名单

差别在于**剥完之后名字还认不认得出来**：

```
一杯茅台  →  茅台     仍然可读，不剥反而是噪音        (a) 直接剥
盒仔茶    →  仔茶     完全失去词义                    (c) 查白名单，不命中就留
```

有数词时，量词是独立的修饰成分；没有数词时，量词可能已经是词的一部分。

### 白名单长什么样

```js
const QW_NOUN = {
  "盒": "牛奶|月饼|鸡蛋|饼干|巧克力|药|纸巾|酸奶|蛋糕|草莓|便当",
  "瓶": "水|饮料|可乐|啤酒|洗发水|沐浴露|牛奶|油|酱油|醋|矿泉水|酒",
  "双": "鞋|袜子|筷子|手套|拖鞋|球鞋|运动鞋|凉鞋",
  // …… 真实项目里 19 组
};
```

只有「盒 + 盒白名单里的词」才剥。`盒仔茶` 的「仔茶」不在名单里，所以不动。

## 为什么接受「漏剥」

看这两类错误的代价：

| | 后果 | 可逆性 |
|---|---|---|
| **漏剥**（该剥没剥） | 名称多带个量词，观感差 | 可逆，用户能手改 |
| **误剥**（不该剥剥了） | 商品名损坏，原始信息丢失 | **不可逆** |

两类错误代价不对称，所以默认选代价小的那一侧：**宁可多留一个量词，也不啃坏一个名字。**

这条后来被写进项目红线：只允许往白名单加词，禁止改回黑名单式的负向断言。

## 30 条断言分三组

| 组 | 测什么 | 条数 |
|---|---|---|
| A | 该剥的剥掉：数词+量词、个、量词+白名单命中 | 14 |
| B | **不该剥的留着**：无动词、量词后接表外词、表外量词 | 8 |
| C | 边界：金额形态、小数、空输入 | 8 |

B 组是这套设计的价值所在——它测的不是「能不能正确剥」，而是「**会不会乱剥**」。

样例：

```
B1  台灯89        →  台灯       无消费动词，完全不碰量词
B2  盘心20        →  盘心       同上（「盘心」是个菜名）
B4  买了盒仔茶12  →  盒仔茶     量词后接表外词，保留
B6  买瓶茅台399   →  瓶茅台     白名单没命中，接受这次漏剥
B7  买了袋装薯片6 →  袋装薯片   「袋」不在词表，不动
```

## 明确不处理的范围

这是最小示例，不是完整引擎。真实项目里这一层之上还叠着：

- **金额位置**：本 demo 只认「名称 + 末尾金额」。真实场景还有金额在前、居中、多笔混合
- **日期归一**：输入法会在数字后补空格，「11 月 3 号」要先压成「11月3号」，否则日期正则整条失配
- **多事件切分**：一句话里有多笔账要先切开，否则归类时只取到一笔
- **规格单位**：`42码的鞋`、`1.5匹`、`65英寸` 里的数字不是金额，要先掩掉
- **分类判定**：剥完名称还要判断这是餐饮/交通/购物

完整引擎约 4,300 行。这里只保留最能说明「取舍」的那 100 行。

---

## 一句话总结

**用黑名单是在赌「我能穷举所有例外」，用白名单是在承认「我穷举不了」。**

后者更可靠，代价是偶尔漏掉本该剥的量词——而那个代价是可逆的。
